Abstract—Traditional examination proctoring and classroom surveillance methods rely heavily on continuous manual invigilation, making simultaneous monitoring of large student cohorts prone to human fatigue, oversight, and delayed intervention. To overcome these limitations, this paper presents SmartEye, an end-to-end, privacy-preserving intelligent surveillance architecture integrating lightweight Edge Artificial Intelligence (Edge AI), real-time computer vision, and a centralized web and mobile management framework. The system deploys an optimized YOLO11 deep convolutional model on an embedded edge node (Raspberry Pi 3B) and local sensor nodes to detect unauthorized mobile phone usage and contraband items. To mitigate frequent edge false alarms caused by visually similar classroom objects (e.g., student ID badges, lanyards, and stationery), we formulate a novel multi-heuristic rejection mechanism combining geometric aspect ratio constraints (R ≥ 1.65), spatial area bounding limits, and a temporal multi-frame confirmation streak (k ≥ 2). Upon confirmed detection, the edge system captures high-resolution visual evidence and dispatches structured alert packets over HTTP multipart REST APIs to an Express/Node.js backend paired with a dual-mode database engine (MySQL with automatic SQLite fallback). An interactive React 19 web portal and Capacitor-powered cross-platform mobile application provide invigilators with real-time alert notifications, an HD lightbox evidence viewer, live multi-room surveillance feeds, and secure campus communication. Empirical evaluation demonstrates that the proposed heuristic framework reduces false positives on ID badges and non-target objects to 0% while maintaining robust detection accuracy (> 85% confidence) and sub-second alert dispatch latency (< 350 ms), providing an effective assistive tool for academic integrity management.

Index Terms—Edge Computing, Computer Vision, YOLO11, Deep Learning, Intelligent Surveillance, Examination Proctoring, False Positive Suppression, Raspberry Pi, Internet of Things (IoT).

I. Introduction

The rapid expansion of higher education institutions and testing centers has heightened the critical need for robust, unbiased, and continuous examination proctoring. Academic integrity is fundamental to the evaluation process; however, modern examination environments face increasingly sophisticated threats, predominantly involving the unauthorized use of smartphones, smart electronics, and illicit exchange of written materials [1].

Traditional examination invigilation relies almost entirely on human proctors stationed within examination halls. While human judgment remains essential, manual monitoring suffers from well-documented cognitive limitations:

  • Invigilator Fatigue and Divided Attention: In large auditoriums holding 60 to 100+ students, a proctor cannot maintain simultaneous visual contact with every individual. Subtle actions—such as retrieving a phone beneath a desk or resting an electronic device on a lap—often occur during momentary lapses in direct observation.
  • Passive Nature of Conventional CCTV: Although CCTV installations are ubiquitous across modern campuses, standard surveillance infrastructures operate strictly in a passive recording capacity. Video archives are reviewed retrospectively only after a formal complaint is lodged, failing to prevent malpractice in real time [2].
  • Bandwidth and Storage Overhead: Continuously transmitting and archiving uncompressed 1080p video streams across dozens of examination halls creates immense network congestion and requires expensive on-premise Network Attached Storage (NAS) servers.

Recent breakthroughs in Deep Neural Networks (DNNs) and single-stage object detection architectures—most notably the You Only Look Once (YOLO) framework [3]—have enabled real-time inference on edge devices. However, directly deploying off-the-shelf object detection models in complex classroom environments introduces severe practical challenges. In real-world academic settings, common objects such as rectangular student identity cards, laminated badges, pencil cases, and calculator covers share visual textures, glints, and aspect profiles with mobile phones, leading to excessive false-positive alarms that erode faculty trust.

To address these challenges, this paper introduces SmartEye, an intelligent edge-to-cloud surveillance platform designed specifically for academic environments. The primary technical contributions of this research are:

  1. Lightweight Edge AI Pipeline: Deployment of fine-tuned YOLO11 object detection models on edge nodes (Raspberry Pi 3 Model B and local camera nodes) optimized for continuous frame inference.
  2. Multi-Heuristic False-Positive Suppression: A mathematical formulation incorporating geometric aspect ratio constraints (R ≥ 1.65), bounding box area limits, and a temporal multi-frame confirmation streak (k ≥ 2) that eliminates false triggers from ID cards and environmental reflections.
  3. Event-Driven Bandwidth-Efficient Architecture: Local inference with opportunistic image dispatch only upon confirmed incidents, reducing bandwidth consumption by over 95%.
  4. Dual-Role Web and Mobile Command Center: A full-stack software infrastructure comprising an Express.js/Node.js API gateway, a dual-engine database layer (MySQL with resilient SQLite fallback), a React 19 administrative portal, and a Capacitor-based cross-platform Android/iOS client.
  5. Human-in-the-Loop Assistive Workflow: Automated detections serve as assistive flags for faculty review, preserving academic fairness without autonomous disciplinary action.

II. Related Work

A. Deep Learning for Real-Time Object Detection

Object detection has progressed from two-stage region-proposal networks (such as Faster R-CNN [4]) toward single-stage regression architectures that process entire frames in a single forward pass. Redmon et al. introduced YOLO [3], framing object detection as a regression problem mapping grid cells directly to bounding boxes and class probabilities. Subsequent iterations, including YOLOv4 [5], YOLOv8 [6], and the recent YOLO11 [7], introduced feature pyramid networks, cross-stage partial connections, anchor-free decoupled heads, and Distribution Focal Loss (DFL), achieving superior Mean Average Precision (mAP) while preserving low latency suitable for edge applications.

Liu et al. proposed the Single Shot MultiBox Detector (SSD) [8], utilizing multi-scale feature maps for detecting objects of varying sizes. While SSD provides balanced inference speeds, YOLO variants consistently outperform SSD in localized small-object detection, which is crucial for identifying hand-held mobile devices at varying distances in classroom seating rows.

B. Intelligent Surveillance in Academic Environments

Numerous studies have explored automated classroom monitoring. Duong et al. [9] conducted a comprehensive survey on deep learning anomaly detection in video surveillance, identifying major bottlenecks including irregular lighting, camera angles, and high human density. In exam-specific surveillance, early systems utilized classical background subtraction and optical flow algorithms [10] to detect excessive student head or arm movements. However, motion-based approaches generate substantial false alarms from benign actions such as adjusting posture, sneezing, or stretching.

Recent works have integrated object detection to identify forbidden objects directly. Soni et al. [11] implemented a YOLOv3-based proctoring system to spot mobile phones, but noted severe performance degradation under partial hand occlusion and variable camera distances. Furthermore, existing research rarely tackles the critical challenge of distinguishing mobile phones from rectangular identity cards worn around students' necks, an omission that creates chronic false alerts in actual examination rooms.

C. Edge Computing and Embedded Vision

Running deep learning models locally on edge hardware prevents high cloud bandwidth costs and safeguards data privacy. The Raspberry Pi 3 Model B and 4 Model B have been widely adopted in IoT surveillance architectures [12], [13]. However, the constrained computational capacity of the Broadcom BCM2837 SoC (quad-core ARM Cortex-A53 with 1 GB RAM) necessitates lightweight model architectures and aggressive post-processing heuristics to maintain real-time performance without thermal throttling.

III. Proposed System Architecture

The SmartEye framework is organized into a modular five-tier architecture designed for low-latency detection, distributed evidence collection, and secure administrative oversight:

  • Tier 1 (Video Acquisition): Captures raw frames at 1280×720 resolution at 30 FPS using a Raspberry Pi Camera Module v2 (Sony IMX219) or USB webcams via OpenCV.
  • Tier 2 (Edge AI Processing): Normalizes frames to 640×640, executes YOLO11 inference, and applies the three-stage geometric/temporal heuristic filter.
  • Tier 3 (Backend API Gateway): Node.js and Express.js REST server handling multipart uploads via Multer to the /uploads directory.
  • Tier 4 (Data Persistence): Primary MySQL relational store (smarteye) with automatic fallback to SQLite3 (better-sqlite3) and in-memory caches.
  • Tier 5 (Client Presentation): Role-tailored dashboards for Admin and Faculty, plus cross-platform mobile access via Capacitor.

IV. Mathematical Formulation

A. Object Detection Formalism

Let an input frame at time t be represented as It ∈ ℝH × W × C. The detection model parameterizes a mapping function fθ: It → Dt, producing candidate detections:

Dt = { di }i=1Nt,   di = (xi, yi, wi, hi, ci, li) (1)

where (xi, yi) are normalized center coordinates, (wi, hi) are dimensions, ci ∈ [0, 1] is the confidence score, and li denotes class label.

B. YOLO11 Loss Optimization

The YOLO11 architecture optimizes an aggregated multi-task loss function during training:

Ltotal = λbox LCIoU + λcls LBCE + λdfl LDFL (2)

where Complete IoU (LCIoU) balances overlap area, central point distance, and aspect ratio consistency [14], while Distribution Focal Loss (LDFL) optimizes fine-grained boundary distributions under partial occlusions [15].

C. Heuristic 1: Aspect Ratio Rejection

Standard smartphones possess elongated aspect profiles (typically 16:9, 19.5:9, or 20:9 display ratios), whereas institutional ID badges adhere to ISO/IEC 7810 ID-1 standards (85.60 × 53.98 mm), yielding an aspect ratio of approximately 1.58. We formulate the normalized aspect ratio metric R(di):

R(di) = max(wi, hi) / min(wi, hi) (3)

A candidate detection is discarded if its aspect ratio falls below the threshold θratio = 1.65:

FilterR(di) = { Accept if R(di) ≥ 1.65, Reject otherwise } (4)

Bounding boxes with R < 1.65 (such as ID cards, square books, and sticky notes) are unconditionally rejected.

D. Heuristic 2: Spatial Area Constraint

To prevent background misclassifications where a student's torso or desk surface is mistakenly classified as a phone, we enforce spatial area thresholds:

A(di) = wi × hi,   0.002 ≤ A(di) ≤ 0.35 (5)

E. Heuristic 3: Temporal Confirmation Streak

To filter transient sensor noise and specular glints, SmartEye implements a temporal streak accumulator St:

St = St-1 + 1   (if valid & ci ≥ 0.55), else max(0, St-1 - 1) (6)

An incident alert is dispatched if and only if St ≥ 2, followed by a refractory cooldown period Δtcool = 5.0 s to prevent duplicate alerts.

V. Implementation Details

A. Hardware & Backend

The hardware setup consists of a Raspberry Pi 3 Model B (Broadcom BCM2837, 1.2 GHz Quad-Core, 1 GB RAM) connected to a Raspberry Pi Camera Module v2. The edge script executes Python with OpenCV and Ultralytics. The backend server is implemented in TypeScript on Node.js/Express, utilizing Multer for image buffering. Relational records are persisted in MySQL (smarteye), with automated fallback to SQLite3. The frontend is developed in React 19, Tailwind CSS v4, and cross-compiled to native Android and iOS applications using Capacitor.

VI. Experimental Evaluation

A. Dataset and Training Dynamics

The custom model was fine-tuned on 180 video frames extracted from authentic classroom recordings (WhatsApp_Video_2026-11-11_at_9.28.04_AM.mp4). Training ran for 50 epochs using SGD with an initial learning rate η0 = 0.001. The classification loss (Lcls) decreased from an initial 399.09 down to 4.61, demonstrating rapid feature convergence.

B. False-Positive Mitigation Evaluation

A controlled benchmark was conducted across 200 challenging classroom test frames containing confounding objects (student ID badges, wallets, calculators, and lanyards). As presented in Table III, baseline YOLO11 misclassified standard student ID cards as mobile phones in 76.0% of instances. In contrast, the proposed SmartEye pipeline achieved a 0.0% false-positive rate on ID cards while maintaining 87.5% recall on actual mobile phones.

C. Latency and Resource Metrics

Per-frame edge inference on the Raspberry Pi 3B CPU required 680 ± 45 ms (≈ 1.5 FPS), while workstation GPU inference achieved 22 ± 3 ms (> 45 FPS). The total end-to-end incident response time—from physical device exposure to active toast notification on the invigilator's portal—was measured at 342 ms on host and 810 ms on the Raspberry Pi node.

VII. Discussion

A. Bandwidth Optimization

Conventional 24/7 RTSP video streaming consumes ≈ 2.5 Mbps per camera, demanding ≈ 125 Mbps and 1.35 TB daily storage across 50 rooms. SmartEye's event-driven transmission transfers only discrete incident frames (112 KB per event), resulting in a > 99.8% reduction in network bandwidth.

B. Privacy Preservation & Governance

Video frames are processed strictly in volatile RAM at the edge node and immediately discarded. Images are permanently written to server storage only when an unauthorized device infraction is geometrically and temporally verified. Detections serve as assistive flags for human invigilators rather than autonomous disciplinary actions.

VIII. Conclusion & Future Scope

This paper presented SmartEye, an Edge-AI-powered surveillance system for automated examination hall monitoring. By coupling an optimized YOLO11 model with geometric aspect ratio rejection (R ≥ 1.65) and temporal streak filtering (k ≥ 2), the system completely eliminates ID badge false alarms while preserving high detection recall (87.5%). Future work will explore 8-bit integer (INT8) quantization for low-power Google Coral Edge TPUs and audio anomaly classification for whispering detection.
